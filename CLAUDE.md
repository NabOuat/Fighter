# Legendz Fighting

2D pixel-art fighting game for mobile (Android first) featuring African historical figures. Godot 4.7.2 Standard, GDScript only (no C#).

The user is a beginner with Godot and works step by step: explain each change in French (what the file does, where to see it in the editor). Code comments are in French.

## Conventions
- Base resolution 480x270, stretch mode `viewport`, aspect `keep_height`, nearest texture filter. Landscape only.
- Renderer: `gl_compatibility` (low-end Android support). Keep it.
- Scripts live next to their scene (`scenes/<feature>/<name>.tscn` + `.gd`). Files and folders in snake_case, `class_name` in PascalCase. Indent with tabs.
- Never hardcode player-facing text: add a key to `localization/translations.csv` (columns `keys,fr,en`) and use the key or `tr()`.
- Character art comes from SpriteLab (prompts: artifact https://claude.ai/artifact/8Lsfg9uxV7JV8LaxLxBpx8 and `docs/spritelab_prompts.md`). Pipeline: zips in Downloads → manifest `tools/sprite_manifests/<hero>_spritelab.json` (zip → animation name, `rescale`, `airborne`, `effect_only`) → `python tools/import_spritelab.py <manifest>` (halves to native pixel size, aligns feet at x center / y 128 on a 192x136 canvas, crops effects) → `Godot --headless --script res://tools/build_sprite_frames.gd -- <hero>` (SpriteFrames `assets/characters/<hero>/<hero>_frames.tres`, creates/updates `data/fighters/<hero>.tres`, wires the special_1 projectile art). `FighterSprite` (child "Sprite" made by `FighterView.use_data`) picks the animation from the fighter state and syncs attack frames to `attack_frame / total_frames`; art scale 1/1.75 with `fight.ART_ZOOM` 1.75 camera (pixel-perfect), follow camera and max fighter gap only when a fighter has art (test fighters keep the old fixed view). Check visuals with `tools/capture_fighter.gd`.
- Fighter stats and texts live in `FighterData` resources (`data/fighters/*.tres`), registered in `GameState.roster` (`autoload/game_state.gd`).
- Design spec (cahier des charges, Claude Doc): https://claude.ai/code/artifact/8224c575-a78f-4241-b6f7-cf007d9a7319 — read it before designing features. Phase 1 (combat prototype with rectangles, 7 steps) is done. Current phase: Phase 2, Pokou arc (Pokou, Dakon, Itsa drawn; 5 stages; story mode with chapter 1 panels); menus, settings, tutorial and fair AI are done. Next: online PvP (Supabase Realtime lobby + WebRTC, waiting on the user's project). The user crops sprite poses manually; `tools/sprite_cutter.py` is an experimental auto-cutter kept for later.
- Fighter (`scenes/fighters/fighter.gd`, `class_name Fighter`) is an enum state machine driven by an `intent` dictionary (filled by player input or, later, AI). It has no `_physics_process`: the arena (`scenes/fight/fight.gd`) calls `poll_input()` then `tick()` on each fighter every physics frame, separates them, then resolves hits by intersecting `get_hitbox_rect()` / `get_hurtbox_rect()` (plain Rect2, no Area2D). Hitstop freezes ticks but not input polling.
- Health is the same for everyone (`Fighter.MAX_HEALTH = 1000`). Stats in `FighterData` are 1-5 (power, defense, speed) + reach. Attacks are `AttackData` resources (frames, damage, hitstun, pushback, knockdown, hitstop, hitbox Rect2 from the feet facing right): a `combo` array, `low_attack`, `air_attack`.
- Generate or restructure `.tres` files with a headless Godot script using `ResourceSaver.save` rather than hand-writing typed arrays.
- Energy (`Fighter.energy`, 0-400, 4 segments): specials and dodge cost 100, ultimate 400; specials, projectiles and assists never grant energy. `AttackData` special fields: energy_cost, chip_damage, dash_speed, projectile (`ProjectileData`), invulnerable_startup, is_ultimate. Special button: short press (<10 frames) fires on release, hold charges.
- Assists: `FighterData.assist` (`AssistData`: ATTACK / PROTECT / HEAL, cooldown 900 frames). The arena sets `Fighter.support`, spawns `Assist` nodes (`scenes/fight/assist.gd`); assist and projectile hits use `receive_attack(..., remote = true)` so a parry never stuns a distant caller.
- No god files: one file = one role. Arena split: `fight.gd` = simulation, collisions, hit resolution, projectiles/assists, menu setup (emits `hit_landed`); `match_flow.gd` (`MatchFlow`, node `MatchFlow`, `fight.flow`) = phases, rounds, timer, announcements; `fight_feedback.gd` (`FightFeedback`, `fight.feedback`) = sparks, sounds, shake, vibration, popups; `match_log.gd` (`MatchLog`) = Arcade match log in user://match_log.csv (`tools/summarize_match_log.py`); `tutorial.gd/.tscn` (`Tutorial`, added only in TUTORIAL mode) = lessons; `scenes/ui/fight_hud.tscn` = display; `training_tools.gd` (`fight.tools`) = dummy modes, test supports, debug keys, opponent `ai`. Fighter split: `fighter.gd` = state machine, `fighter_view.gd` (`FighterView`, node `View`) = rectangles + attack markers (startup outline, blue down arrow LOW, orange up arrow HIGH, purple hand THROW; `Fighter.show_markers`), `player_input.gd` (`PlayerInput`) = reads Input into `intent`.
- Scripts reachable from `Fighter` (and anything a test script types statically) must not use the `GameState` autoload identifier: test scripts compile before autoloads exist. The arena passes settings to fighters instead. In tests, use `await use_test_settings()` (test_base): it waits for GameState, then `reset_settings("user://test_settings.cfg")` so tests and tools (e.g. `tools/capture_screens.gd`, screenshots of every screen) never read or write the player's real settings.
- Menus (`scenes/menus/`): `MenuScreen` base (Android back / ui_cancel → `go_back()`), title → main menu → fighter select → fight. `GameState.Mode` QUICK (fight scene run alone with F6, test tools and keys M/R), ARCADE (6 fights, `MatchResult` window), TRAINING, TUTORIAL. Navigation via `GameState.go_to()` (`dry_run` in tests). Settings (ConfigFile user://settings.cfg, `settings_saved` signal): language, Music/SFX buses, vibration, attack markers, extra touch buttons (Throw, Special2, LowAttack, Charge; with Charge, Special fires on press), touch layout (normalized positions + scale per button, opacity, right/left-handed presets). Theme `ui/legendz_theme.tres` from `tools/make_ui_theme.gd`; `UiSound` autoload clicks every button.
- Game feel: `HitEffects` (sparks, parry ring), `SoundBank` (placeholder WAVs from `tools/make_placeholder_sounds.py`, replace by dropping same-named files in `assets/audio/sfx/`), camera shake on heavy hits/KO, `PauseMenu` (pause action, tree paused).
- Match flow (`MatchFlow.Phase`: INTRO, FIGHT, ROUND_OVER, MATCH_OVER): 2 winning rounds, 60 s timer (ticks only on simulated frames), KO slow motion, draws count for both. Each round resets health, energy (0) and assist cooldown. Controls are released outside FIGHT. Training: `Fighter.immortal`, no timer, full energy.
- Throw: `FighterData.throw` (`AttackData.is_throw`), forward + guard press (or `throw` action) within `Fighter.THROW_RANGE`; unblockable, misses airborne/stunned targets (`HitResult.MISSED`), simultaneous throws tech (`HitResult.TECHED`). Combo presses during an attack are queued (`chain_queued`) so fast tapping never drops a hit.
- AI: `FighterAI` (`scenes/fighters/fighter_ai.gd`, RefCounted) fills `Fighter.intent` each frame like a player would (no rule cheating); difficulty (EASY/NORMAL/HARD) only changes reaction time and choice quality (`SETTINGS`): it only "sees" an attack after `reaction` frames, guesses guard height (HARD learns the player's low/high ratio), holds guard through block strings, throws turtling opponents. Balance it with headless AI-vs-AI tournaments (`--fixed-fps 60`).
- Story mode (`GameState.Mode.STORY`): content in `scenes/story/story_data.gd` (`StoryData.POKOU_ARC`: chapters of steps, `{"panels": [...]}` or `{"fight": {player, opponent, rule duel|survival|boss, difficulty, stage, fallback_stage, intro, waves/phases, seconds}}`; `UNLOCKS`), progress and unlocks in `StoryProgress` (`GameState.story`, user://progress.cfg; Pokou, Sékou, Béhanzin playable from the start, a defeated fighter becomes a support, finishing the arc makes it playable). Screens `story_map` (chapters) and `story_panels` (griot panels, `assets/story/pokou/<name>.png`, text `STORY_<NAME>`, missing image = placeholder card); `GameState.play_story_step()` / `story_next()` route between them. `MatchFlow.Rule` (VERSUS, DUEL, BOSS, SURVIVAL) via `flow.configure()`; between boss phases / waves the player keeps health (+20 %) and energy, the AI gets stronger. Story-only fighters (`guerrier_itsa` = tinted Dakon via `FighterData.tint`, `genie_comoe` placeholder) come from `tools/make_story_fighters.gd` and are not in the roster (`GameState.fighter_by_id` loads them). `playable_roster()` / `support_roster()` filter by unlocks; tests reset progress with everything unlocked.
- 2D physics layers: 1 decor, 2 fighters (fighters don't collide with each other; the arena pushes them apart).
- Input actions (simple control mode): `move_left`, `move_right`, `jump`, `crouch`, `attack` (J), `special` (K), `guard` (L), `assist` (I), `ultimate` (U), `pause`. Punch/kick will come back with the technical mode.
- Historical accuracy matters: check facts (dates, kingdoms) before writing bios.
